# 用户画像平台一期 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 用户画像平台 |
| 版本 | Phase 1 / MVP |
| 目标用户 | 业务、运营、数据、数据管理员 |
| 建设方式 | 业务系统 + 数仓计算能力 |
| 一期标签主体 | 用户，主键统一为 `uuid` |
| 输入资产 | 存量标签元数据、画像宽表、标签质量统计、飞书需求记录 |

## 2. 背景与问题

当前已有用户画像标签治理基础，包括标签分类、编码、状态流转、元数据表和存量标签草稿。现阶段如果只用 BI 做标签地图，会遇到几个限制：

- BI 更适合展示统计结果，不适合承载标签详情、圈选规则、导出审批和审计闭环。
- 标签元数据、需求流转、权限策略、人群包和导出任务无法在 BI 中形成统一业务对象。
- 运营和业务需要的不只是“看标签”，还包括“找标签、懂口径、圈人群、可导出、可追溯”。
- 用户级明细、联系方式、设备标识、订单支付等敏感数据不能通过普通看板能力直接开放。

因此一期目标不是建设复杂画像中台，而是先建设一个可落地的画像平台 MVP，把现有标签治理资产产品化。

## 3. 一期目标

一期要解决 5 类核心问题：

| 目标 | 说明 |
| --- | --- |
| 标签可查 | 业务能按名称、编码、分类、产品、区域、状态、负责人检索标签 |
| 口径可信 | 每个标签能看到业务口径、技术口径、值域、来源、产出和负责人 |
| 人群可圈选 | 运营能用标签条件组合圈选用户，并预估人群规模 |
| 导出可受控 | 已授权用户可提交导出任务，导出经过审批、有效期和审计控制 |
| 治理可闭环 | 数据侧能看到质量问题、需求状态、标签状态和审计记录 |

## 4. 一期范围

### 4.1 本期做

| 模块 | 一期能力 |
| --- | --- |
| 首页概览 | 标签总数、已上线标签、敏感标签、质量问题、待处理需求、导出任务概览 |
| 标签目录 | 标签搜索、筛选、排序、状态标识、敏感等级标识 |
| 标签详情 | 基础信息、业务口径、技术口径、值域说明、质量状态、负责人和需求链接 |
| 标签地图 | 按一级分类、二级分类、产品、区域、状态展示标签分布 |
| 人群洞察 | 基于标签条件查看人群规模、覆盖率、值分布和趋势 |
| 人群圈选 | 支持标签条件组合、规模预估、保存人群包 |
| 人群导出 | 支持提交导出申请、审批状态、导出结果位置和过期时间 |
| 质量监控 | 展示覆盖率、空值率、最近分区、任务状态和异常标签 |
| 需求看板 | 展示标签需求从提出到上线的状态流转 |
| 权限审计 | 标签查看、圈选、保存人群包、导出申请均记录审计 |

### 4.2 本期不做

- 不建设实时标签计算引擎。
- 不把全量用户标签明细搬到业务库。
- 不做复杂多层嵌套规则编辑器。
- 不直接打通 CRM、Push、短信等触达系统。
- 不开放无审批的大规模用户级明细导出。
- 不纳入图片、视频、模型等非用户主体标签。

## 5. 用户角色与权限边界

| 角色 | 典型诉求 | 默认权限 |
| --- | --- | --- |
| 业务用户 | 查标签、看口径、提需求 | 查看标签目录、标签详情、聚合统计 |
| 运营用户 | 圈选人群、保存人群包、申请导出 | 可圈选普通标签；敏感标签和导出需授权 |
| 数据同学 | 维护口径、看质量、排查问题 | 查看技术口径、质量指标、调度和治理信息 |
| 数据管理员 | 管权限、审导出、查审计 | 管理权限、审批导出、查看审计日志 |

无权限时，不展示数据明细，只提示需要申请的资产名或权限入口。

## 6. 核心业务流程

### 6.1 标签查询流程

```text
进入标签目录 -> 搜索/筛选标签 -> 查看标签详情 -> 判断是否可用 -> 进入圈选或提交新需求
```

### 6.2 人群圈选流程

```text
选择标签 -> 配置条件 -> 预估人数 -> 保存人群包 -> 记录业务用途 -> 写入审计
```

### 6.3 人群导出流程

```text
选择人群包 -> 填写导出用途 -> 选择导出目标 -> 权限校验 -> 审批或直接完成 -> 生成结果 -> 写入审计
```

### 6.4 标签需求流程

```text
飞书表单提需 -> 进入需求看板 -> 复用检查 -> 元数据预登记 -> 数据开发 -> 业务验收 -> 状态更新为已上线
```

## 7. 产品功能设计

### 7.1 首页概览

展示平台运行概况，帮助数据侧快速识别治理风险。

核心指标：

- 标签总数、已上线标签数、暂停/下线标签数
- 敏感标签数
- 质量异常标签数
- 人群包数量
- 待审批导出任务数
- 待处理需求数

### 7.2 标签目录

筛选条件：

- 标签名称 / 标签编码 / 来源表 / 产出字段关键词
- 一级分类、二级分类
- 适用产品、适用市场/区域
- 标签状态
- 标签值类型
- 敏感等级
- 数据负责人

列表字段：

- 标签名称、标签编码
- 一级分类、二级分类
- 适用产品、适用区域
- 标签值类型、标签状态
- 敏感等级
- 产出表、产出字段
- 数据负责人、最近更新时间

### 7.3 标签详情

标签详情页按“业务先读懂，数据可追溯”的顺序展示：

- 基础信息：标签名称、编码、分类、适用产品、适用区域、状态
- 业务口径：业务定义、适用场景、统计周期、更新频率、数据时效
- 标签值说明：值类型、字段类型、枚举含义、空值含义
- 技术口径：来源表、产出表、产出字段、调度任务
- 质量信息：覆盖率、空值率、最近分区、任务状态
- 治理信息：业务负责人、数据负责人、版本、需求链接、备注

### 7.4 标签地图

标签地图不是单纯展示图，而是标签资产导航入口：

- 顶部提供轻量资产定位入口，可按分类、产品、区域、状态快速定位资产，不作为主要搜索功能；完整搜索仍在标签目录完成。
- 以二级分类为核心展示标签资产概览，一级分类只作为分组信息。
- 二级分类概览需展示标签数量、已上线数量、敏感标签数量、监控覆盖率和质量风险数量。
- 按产品、区域、状态、敏感等级、标签值类型展示分布。
- 展示基于元数据规则生成的治理提示，包括高敏标签、监控覆盖不足、非上线标签占比高、分类资产过薄等；不做没有数据来源的泛化“体系洞察”。
- 点击二级分类或分布项后，联动跳转到标签目录筛选结果。

### 7.5 人群洞察

用于判断标签是否适合业务使用：

- 单标签或少量标签条件预估覆盖人数。
- 展示覆盖率、值分布和趋势。
- 默认只展示聚合结果，不展示用户级明细。

### 7.6 人群圈选

一期支持轻量规则：

| 能力 | 一期设计 |
| --- | --- |
| 条件字段 | 只能选择已上线、当前用户有权限的标签 |
| 操作符 | 等于、不等于、包含、大于、小于、区间、为空、不为空 |
| 组合逻辑 | 支持全局 `AND` / `OR`，暂不支持复杂嵌套 |
| 人数预估 | 基于数仓查询返回聚合人数 |
| 保存人群 | 保存人群名称、用途、条件 JSON、预估人数、创建人、状态 |
| 版本追溯 | 人群条件变更生成版本，历史导出仍可追溯原始条件 |

### 7.7 人群导出

导出能力按受控原则设计。

导出字段：

- 默认字段：`uuid`、人群包 ID、命中标签摘要、创建时间。
- 敏感字段：邮箱、手机号、设备 ID、IP、订单号、支付号等默认不允许导出。
- 如确需导出敏感字段，必须走单独审批。

导出目标：

- CSV 文件。
- 一期导出到服务端本地文件，平台提供下载入口。
- 后续可扩展 ODPS / MaxCompute 结果表、CRM、Push、短信等目标。

导出控制：

- 大人群导出走审批。
- 使用敏感标签圈选的人群导出走审批。
- 导出结果必须有有效期。
- 导出记录必须可审计。
- 审批接飞书审批，平台保存飞书审批实例 ID、审批状态和审批链接。

导出流程：

```text
提交导出申请 -> 平台写入导出任务 -> 发起飞书审批 -> 审批通过 -> 异步生成本地 CSV -> 写入结果路径 -> 用户下载 -> 到期清理
```

### 7.8 质量监控

一期质量监控关注“能否放心使用”：

- 最近分区是否产出。
- 调度任务是否成功。
- 覆盖率是否异常。
- 空值率是否异常。
- 元数据是否缺失口径、负责人、来源表、产出字段。

### 7.9 需求看板

需求看板承接飞书需求表单，不替代业务提需入口。

状态流转：

```text
需求中 -> 口径确认中 -> 待开发 -> 开发中 -> 待验收 -> 已上线
```

暂停或废弃需求进入：

```text
暂停使用 / 已下线
```

## 9. 技术选型

### 9.1 推荐结论

一期推荐采用：

```text
React + Ant Design + NestJS + MySQL 8.0 + Redis + MaxCompute/DataWorks + 飞书审批
```

后端建议优先选 `Node.js / NestJS`，原因是一期核心是内部运营平台和数据资产管理，主要处理元数据、规则 JSON、飞书表单、飞书审批、导出任务和数仓查询编排。NestJS 开发效率高，结构比普通 Node.js 更规范，适合快速验证；后续如果公司统一要求接入既有 Java 业务系统，再按稳定后的接口和表结构迁移到 Spring Boot。

不建议一期直接做重 Java 后台或复杂画像引擎。当前重点是把业务流程、表结构、权限审计和圈选导出闭环跑通。

### 9.2 模块选型

| 模块 | 推荐选型 | 说明 |
| --- | --- | --- |
| 前端 | React + Ant Design | 内部后台系统成熟、组件齐全 |
| 后端 | Node.js / NestJS | 一期快速验证，适合规则 JSON、飞书集成、异步任务编排 |
| 业务库 | MySQL 8.0 | 存平台业务对象、权限、任务和审计 |
| 数仓计算 | MaxCompute / DataWorks | 标签宽表、人群预估、导出结果 |
| 缓存 | Redis | 标签目录缓存、圈选预估缓存、导出任务锁 |
| 导出文件 | 服务端本地文件 | 一期先导出到本地，记录文件路径和过期时间 |
| 身份认证 | 公司 SSO / 飞书身份 | 用户身份、部门、角色映射 |
| 导出审批 | 飞书审批 | 人群导出申请走飞书审批，平台记录审批实例和状态 |
| 权限模型 | 平台权限表 + 数据资产权限 | 标签、人群包、导出三类权限分开控制 |

### 9.3 业务库快速验证方案

业务库最终按 MySQL 8.0 设计。一期为了快速验证，不等生产业务库资源，可以先用本地 Docker MySQL 跑完整表结构和流程。

验证方式：

```text
本地 Docker MySQL -> 初始化 profile_* 表 -> 导入存量标签元数据 -> 启动 NestJS -> 本地页面验证目录、圈选、导出、审计
```

本地验证建议：

- 使用 MySQL 8.0 Docker 容器，避免 SQLite 和正式 MySQL 方言差异。
- 使用同一套 DDL，后续迁移到正式业务库时不重写表结构。
- 存量标签元数据由 CSV 或数仓表同步到 `profile_tag_metadata`。
- 人群圈选在本地阶段可用样例用户数据验证交互，联调阶段再切到 MaxCompute 查询。
- 本地导出文件落在服务端目录，例如 `storage/exports/{export_task_id}.csv`。

正式环境：

- 业务库使用公司已有 MySQL 集群。
- Redis 用于缓存标签目录、人群预估结果和导出任务锁。
- 导出文件仍先落服务端本地或挂载盘；如果后续有合规要求，再迁移 OSS。

### 9.4 关键技术原则

- 业务库不存全量用户标签明细，只存平台管理数据。
- 人群圈选计算默认下推到 MaxCompute。
- 导出大任务异步执行，不阻塞 Web 请求。
- 一期导出结果落本地文件，必须设置过期时间并支持清理。
- 权限校验和审计写入必须集中封装，不散落在页面或 SQL 中。

## 10. 权限与审计设计

### 10.1 敏感等级

| 等级 | 示例 | 展示策略 |
| --- | --- | --- |
| 普通 | 活跃等级、功能偏好、生命周期 | 可展示目录、口径和聚合统计 |
| 中敏 | 风险等级、会员状态、消费层级 | 圈选和导出需校验权限 |
| 高敏 | 邮箱、设备 ID、IP、订单号、支付号、用户级明细 | 默认不展示明细，导出必须审批 |

### 10.2 审计动作

必须审计：

- 查看敏感标签详情。
- 使用标签条件预估人群。
- 保存人群包。
- 提交导出任务。
- 审批导出任务。
- 下载或同步导出结果。

审计失败时，不允许继续展示敏感数据或生成导出结果。

### 10.3 飞书审批接入

人群导出审批接飞书审批。平台自身不重新建设复杂审批流，只负责发起审批、记录审批实例、同步审批状态，并在审批通过后执行导出。

审批单建议字段：

| 审批字段 | 来源 |
| --- | --- |
| 申请人 | `profile_export_task.requested_by` |
| 导出用途 | `profile_export_task.business_purpose` |
| 人群包名称 | `profile_audience_package.audience_name` |
| 圈选条件摘要 | `profile_audience_package.condition_json` 生成摘要 |
| 预估人数 | `profile_audience_package.estimated_user_cnt` |
| 导出字段 | `profile_export_task.export_fields` |
| 导出目标 | 固定为本地 CSV |
| 结果有效期 | `profile_export_task.expire_time` |
| 风险等级 | 根据敏感标签、导出字段、人数规模计算 |

审批状态映射：

| 飞书审批状态 | 平台状态 |
| --- | --- |
| 审批中 | `pending` |
| 通过 | `approved` |
| 拒绝 | `rejected` |
| 撤回 / 取消 | `cancelled` |
| 导出完成 | `completed` |

## 11. 验收标准

| 模块 | 验收标准 |
| --- | --- |
| 标签目录 | 可基于存量元数据完成搜索、筛选、查看详情 |
| 标签详情 | 能展示业务口径、技术口径、值域、负责人、质量状态 |
| 标签地图 | 能以二级分类展示资产概览，覆盖产品、区域、状态、敏感等级和值类型分布，输出规则化治理提示，并可联动目录筛选 |
| 人群圈选 | 可用标签条件组合预估人数，并保存人群包 |
| 人群导出 | 可提交导出任务，审批状态、结果位置、有效期可追溯 |
| 质量监控 | 可展示覆盖率、空值率、任务状态和异常标签 |
| 需求看板 | 可展示需求状态流转，关联飞书需求记录 |
| 权限审计 | 敏感标签、圈选、导出均有权限控制和审计记录 |
