# 标签地图资产概览设计

## 背景

当前标签地图只展示一级分类树和产品、区域、状态分布，和首页概览有明显重复。它没有突出二级分类，也没有把分布项联动到标签目录，导致“地图”更像静态图表。

## 目标

标签地图定位为标签资产概览和导航入口，回答三个问题：

- 哪些二级分类沉淀了标签资产，数量、上线情况、敏感标签和监控覆盖如何。
- 标签资产在产品、区域、状态、敏感等级、值类型等维度上如何分布。
- 哪些分类或标签集合需要治理关注，并且可以跳转到标签目录继续处理。

## 非目标

- 不把标签地图做成标签搜索页；搜索只作为轻量定位入口。
- 不做没有规则来源的“智能洞察”；本轮只做基于元数据字段生成的治理提示。
- 不改造标签目录、人群圈选等其他模块的业务逻辑。

## 页面结构

1. 顶部保留标题说明，增加居中的“资产定位”输入框和进入标签目录按钮。输入框用于快速定位分类、产品、区域或状态，不作为强搜索主入口。
2. 主体展示二级分类资产矩阵。一级分类只作为分组信息，二级分类卡片展示标签数、已上线数、敏感标签数、监控覆盖率和质量风险。
3. 右侧展示治理提示，规则来自元数据聚合，包括高敏占比、监控缺失、非上线占比、结构过薄等。
4. 下方展示产品、区域、状态、敏感等级、值类型分布。产品、区域、状态、敏感等级和分类项可跳转到标签目录筛选结果。

## 数据契约

`GET /api/tag-map` 继续保留原有字段，并新增：

- `category_assets`：二级分类资产列表。
- `sensitivity_distribution`：敏感等级分布。
- `value_type_distribution`：标签值类型分布。
- `governance_insights`：规则化治理提示。

`GET /api/tags` 新增支持：

- `categoryL2`
- `valueType`

## 验收

- 标签地图首屏以二级分类资产矩阵为主体，搜索入口视觉弱化且居中。
- 二级分类、产品、区域、状态、敏感等级分布项点击后能跳转到标签目录并带上筛选条件。
- 治理提示必须能解释其规则来源，不能展示空泛结论。
- PRD 中 7.4 和验收标准同步反映上述能力。
